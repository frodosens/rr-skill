# 制作日式 Godot 建筑

先确定建筑用途和场地接口，再离线生成模型。分别证明模型正确、场地可放、入口可达、实际驾驶和设备性能，不用一个 PASS 代替全部验收。

## 读相关参考

- 找源模型、生成器和版本边界：读 [来源索引](references/source-map.md)。
- 做住宅、商店或旅馆：读 [离线建模](references/offline-authoring.md)。
- 放置建筑、清理旧宅地或接入口：读 [宅地与集成](references/site-integration.md)。
- 导入、雪天、LOD、实例与交付：读 [验证与运行成本](references/validation.md)。

## 1. 冻结范围和来源

1. 核实当前工程、Git 远端、分支、未提交修改、目标场景及资源哈希。不要由目录名猜仓库身份，不用旧整包覆盖现有文件。
2. 区分模型源、独立样板、场地规划、保存的候选、隔离驾驶验证、主游戏集成和已发布版本。以输入哈希和验收对象判定，不能只比较 v3/v4/v5 名称。
3. 确定本次是普通房屋变体、特殊建筑还是宅地集成。复用已有尺度、色板、锚点和资源命名空间；新建筑方向先做一栋可检查样板。
4. 将目标写成合同：米制尺寸，原点/朝向，LOD 和材质面数，入口/服务门，完整足迹，碰撞所有者，天气通道，受保护邻接物，允许改动的场地范围。
5. 若没有来源索引中的脚本，先定位当前等价实现。不要假装历史工作区存在，也不要把建议包装成已实现工具。

## 2. 选择真实制作管线

**普通住宅和无品牌商店**：使用空输入网格、真实 Geometry Nodes 网络，分别建立 LOD0/LOD1。按宽、深、层数、层高、开间、屋顶升高和墙材质生成。离线求值后导出 GLB，不让 Godot 运行 Blender 节点。

**温泉旅馆和特殊建筑**：使用 Blender Python 的显式 Mesh 体块、屋顶、窗组和附属物组合。不要称现有旅馆为 Geometry Nodes，也不要把普通住宅单纯拉伸成旅馆。保持主入口、客房翼、后勤和浴场的空间层次；现有资产无室内房间布局或可交互门的保证。

**共同要求**：保持单位根变换、Godot +Y 向上、+Z 为前门、基底 y=0；保留可重建源和参数。用大面轮廓、屋檐、木构节奏和有限色板建立风格，优先不透明窗和共享材质。参数范围不是所有组合都已通过的保证。

## 3. 构建可集成资产

1. 检查四面窗框朝向、首层整组窗与门的排除、屋顶/墙体接缝、闭合屋顶与退化面。不要只检查正立面。
2. 将屋檐、入口与服务台阶纳入实际导出包络。从保存的 GLB 核对尺寸，不能用墙体设计尺寸代替全资产足迹。
3. 在合同及 Godot 场景保存 FrontDoor、FrontStep；有后勤门时保存 ServiceDoor、ServiceStep，保证世界变换后朝向正确。
4. 保留 Color.rgb 的着色和 Color.a 的雪曝光语义。Color.a 不是透明度；屋檐下台阶与露天台阶分别标注。不要让普通透明着色器误用此通道。
5. 用真实减少细节的 LOD，保留轮廓、入口位置和足迹。共享外部材质，核验导入器是否又自动生成一套 LOD。
6. 资产碰撞模板默认禁用，layer/mask 为 0。经当前场景碰撞 owner 审核后才按授权集成，不能一键启用全部可见网格碰撞。

## 4. 先宅地，再入口和装饰

1. 从当前保存的原生地形/道路三角形与最终建筑网格计算世界足迹和支撑。检查完整相交域与外扩域，不只采样根点或四角。
2. 使用真实门和台阶锚点连到步道；保留门口标高，但不要把整条起伏步道锁成同一高度。区分铺装外观、实际支持面、碰撞面和交通路径。
3. 分开停车矩形、人行连接、后勤通路、车辆完整包络和车轮支撑域。静态车位放得下不能证明能进出、倒车或开门。
4. 核验邻屋、商店视线、树木、围栏、盆栽、基础和旧路的保留约束。更改地形时检查外羽化坏面与所有旧物脚位，不只检查轮胎经过处。
5. 清理旧宅地前，先按原生几何和资源连通分量确认归属。共享院地、批次或栏杆不能按名字整组删除。加 before-state guard，并验证重复调用不改变场景。
6. 新增房屋先放少量、分层构图，避免为补数量塞满空场。最后添加经预算的小物，不用装饰掩盖悬空、穿插或不可达入口。

## 5. 分层验收和交付

按 [验证与运行成本](references/validation.md) 从保存资产、引擎资源、场地支撑到实际运行逐层测试。雪天、实例化、LOD、碰撞与设备性能分别记录。

失败时保留真实日志、哈希和具体门槛。不要放宽阈值、移动受保护对象、瞬移车辆或删除封栏来制造通过。已封闭的入口只在其当前候选通过所需验收且授权允许时开放。

交付生成器/源模型、导出模型、Godot 场景、合同、确切变更、实际截图及通过/失败/未运行清单。未运行设备测试就不承诺手机 FPS；历史独立样例或静态继承不能代替当前世界重验。
