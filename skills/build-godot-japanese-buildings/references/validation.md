# 分层验证与运行成本

## 1. 源与实际 GLB

- 对源、参数、依赖、模型、合同和图像记录 SHA-256。再生成时不得把旧 PASS 当新模型结果。
- 检查 GLB accessor/索引、实际三角形、退化面、法线、单位根变换、实际 AABB、材质面和 Color 通道。
- 检查首层门窗不相交、背面窗框朝外、屋顶/墙体贴合、檐下/露天台阶曝光、LOD 外形与足迹。
- 改 GN 参数时测实际求值结果并恢复，不能只证明参数面板存在。历史宽8→12m试验是一例，不覆盖所有范围组合。
- 用重导入实际 GLB 的预览检查四面、近景和比例。Blender 原场景漂亮不能证明导出的模型相同。

## 2. Godot 导入、资源与生命周期

普通建筑的 `run_checks.sh` 先导入，关闭 GLB import 的 `meshes/generate_lods` 再重导入，构建场景后测试。使用隔离 HOME/XDG 目录，并核对工具版本。不要从别的工程复制 `.godot` 缓存来绕过导入。

核对：
- 实际加载的 MeshInstance/表面数与三角形一致；
- 共享材质资源身份一致，未无意为每栋复制材质；
- FrontDoor/FrontStep 和后勤锚点存在，位置/朝向正确；
- 默认模板碰撞禁用，未意外新增 active collider；
- LOD 范围连续、足迹一致，装卸后无残留节点/遮蔽注册；
- 晴→雪→晴与反复装卸稳定，材质未串改或恢复丢失。

历史40次装卸、7材质身份和15613项检查是特定资产的资源证明，大量是逐顶点检查；不能称为15613个独立场景。

## 3. 场地与保存读回

验证最终原生场景，不只作者临时数组。检查完整地形三角支持、所有新旧脚位、门阶接口、保护域、共用资源与碰撞 owner；更改世界 transform/地形后旧支持结论失效。

若使用 MultiMesh，dummy/headless getter 可能返回身份变换。优先从可信保存的 float32 buffer 重建实例并乘完整父 transform，检查 stride、instance_count 与格式；或在真实 renderer 下交叉验证。不要将错误的 identity 结果当作“树都不挡路”。保存格式/flags 改变时重写解析，不盲套12或16浮点步长。

独立复审应从保存资产重新提取，不仅重复作者生成器的预期数组。限定继承必须证明变化后几何为旧包络子集、脚位/依赖不变等具体条件，清楚写未重跑的部分。

## 4. 实际运行与视觉

- 跑原车辆的连续输入、四轮接触、车体碰撞/完整包络、停车保持和倒出。开始出生后不能中途瞬移、重置速度或换临时小车来通过。
- 分开路线可执行、严格接触检查、交通汇入/行人冲突。最大约1.09m/s的隔离低速测试不能证明高速或主路动态交通。
- 使用原封栏负对照时记录明确失败目的。仅在隔离运行临时移栏不能成为删除源场景栏杆的依据。
- 实际 GPU 下查看正面、背面、入口近景、邻房/店面视线、LOD 临界点，以及晴雪和恢复后的同机位图。
- 保留失败帧和完整日志。原车预览到达终点但有严格子接触失败时，分别报告，不写全通过。

headless dummy renderer 只可证明加载/逻辑/资源与适用的物理检查，不证明 GPU 雪着色、视觉质量或 Android。抽帧/软件渲染预览上的 FPS 不能用作持续性能结论。

## 5. 性能预算

显式区分单资产三角形、每实例成本、材质 surface、实际 GPU draw calls、帧时间和内存。资源复用不是零绘制，surface 数也不是实测 draw calls。

历史普通建筑 110m/420m 是硬切换范围示例，不是适用于所有地图的常数。先验证实际镜头和移动方向的 pop、空档、双层重叠与远景消失，再调整。LOD0/1 各自共用材质不应破坏雪参数的实例/区域语义。

历史4A+4B+3C加商店约18066个近景三角形，未含院落小物；不能把单栋预算推广成整村小于12k。旅馆远 LOD 仍有4516三角形，需另算。

优化建议按需采用并实际验证：
- 删远景窗棂、小招牌、屋顶细线和小物；保留大轮廓与入口识别。
- 按空间分组复用 mesh/材质，评估 MultiMesh 与剔除效率，而非把全村合成一大批。
- 保持不透明低复杂度材质，避免每栋灯光、透明玻璃、实时反射和逐帧几何生成。
- 在真实目标设备连续驾驶测试晴、雪、LOD/流送切换和密集街区，记录设备/分辨率/renderer/构建版本、CPU/GPU帧时间、内存与温升下的稳定性。

没有设备数据时，只交付几何/资源预算和未测声明，不承诺手机帧率。
