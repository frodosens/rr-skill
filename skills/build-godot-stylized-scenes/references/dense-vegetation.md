# 密集植被与 GPU 风动

后续制作密集草丛、草甸和适合面片表达的低矮植被，默认复用已选的五片交叉草丛方案。将它视为制作方法，不视为全图铺设授权、已完成正式场景集成或移动端性能通过。保持现有地形、道路、车辆、画质设置与区块所有权；新方向或明显风险变化另行确认。

## 1. 草丛几何与根部风动

- 近景每丛用五张交叉面片，合在同一个 mesh surface 和共享材质中；不要为五片分别建节点或提交绘制。面片固定朝向，不随镜头旋转。
- 沿高度分段以形成弯曲。027 样板每片三段，因此近景每丛为 30 个三角形，不是五个三角形。按剪影需求调节段数与面片数，而不是盲目增加密度。
- 用归一高度 `h = clamp(UV.y, 0, 1)`，约定根为 0、尖为 1。顶点位移采用 `风向 × 风强 × 波形(世界位置、时间、实例相位) × h² × 实例尺度`，并与距离淡出及雪天高度变化一致。根部位移必须严格为零；半高位移为同等条件叶尖的四分之一。
- 在 GPU 顶点着色器中计算风，以世界方向统一弯曲方向、空间阵风和每丛相位打散同步。CPU 只更新少量共享参数和低频块级 LOD，不逐帧重建草网格、重撒点或更新每丛变换，不创建每丛节点、骨骼或碰撞。
- 使用有 mipmap 的 alpha cutout 轮廓，避免把密集草改成 alpha blending。交叉面片仍有透明裁切和像素重叠成本；低 draw call 不代表低填充率成本。027 的向上法线是风格化光照选择，并非物理弯曲法线。

## 2. 分块、LOD 与剔除

- 按小空间块组织 MultiMesh，由现有世界流送区块拥有和回收；不要创建覆盖整图的单个巨型 MultiMesh。共享单 surface/单材质，默认关闭草投射阴影和草碰撞。
- 保持固定 seed、稳定实例顺序、色差与相位。LOD 同时降低面片数、纵向分段和实例密度；在同一节点切 mesh/可见实例数，避免多档长期重叠绘制。
- 将距离、密度和更新频率作为可配置起点，并服从现有画质档。027 样板使用 12 m 小块、近/中/远 30/12/4 三角每丛、24/48/96 m 距离、100%/65%/30% 密度、3 m 迟滞及 4 Hz 块级更新；这些不是通用或手机合格参数。
- 从最终地形与实例变换计算真实 AABB，加入草高、叶宽和最大风位移。考虑 chunk 半对角线与迟滞，让剔除发生在草已淡出之后；禁止搬用平地样板的固定高度包围盒。
- 检查急转镜头、进入/离开区块和往返跨 LOD 的闪现与跳变。027 使用硬 mesh/密度切换与迟滞；必要时加互补抖动过渡，但重新计算过渡时的重复绘制与 overdraw。

## 3. 真实地表与遮罩

- 从权威最终地表采样草根高程，沿用 surface catalog、owner、seed 和支持检查；不要复制样板的 `ground_height`、`path_center`、固定网格或背景地形。
- 复用道路、路肩、车道接入、建筑/门阶、岩石、水体和视线保留域。道路排除不只查根点，还要覆盖叶宽及最大风偏移，防止叶片摆进路面。
- 在道路边缘、林缘与草甸使用连贯密度场，不把所有允许区域铺成等密度草毯。保存后用实际 GL 读回实例并核验接地、道路排除和 bounds，不能以 dummy/headless 输入检查代替渲染读回。
- 大世界若有原点重定位，保持稳定世界相位或同步偏移，避免重定位时全场风动跳变。

## 4. 雪天与远景地表衔接

- 接入现有天气系统，以共享 uniform 控制压低、稳定稀疏和淡色，保持根固定并精确恢复晴天。027 冬季高度 46%、稳定剔除 58% 是效果样例，不是积雪模拟。
- 深雪时从 CPU 减少可见实例或跳过埋雪块。fragment discard 不减少顶点提交，不能把雪天白色或丢弃像素误报为几何节省。
- 在细节草淡出后保留匹配的地表草甸颜色、低频明暗和必要的纹理。按实际受光后的草丛总体色匹配地面，避免细节半径外突然变裸地或露出圆环。
- 区分近地驾驶和高位总览策略，不靠无限增大 3D 草距离解决远景。027 在 63–83 m 压低淡出、96 m 块级剔除；这些只作样板起点，正式范围按镜头与设备重新选择。

## 5. 已有证据与性能边界

027 样板为 96×96 m、64 块、31,135 丛；实例缓冲估计 1.90 MiB，不含引擎开销。已核对 `grass_wind027/evidence/draw_call_profile.json`：同相机草开/关差值为近景 **32**、宽景 **46**、高位总览 **52** 个 draw call。不要把 64 个总块数当成每个视角实际提交量，也不要把五张面片当成五次提交。

测量条件为 Godot 4.6.3 Compatibility、1280×800、云端 llvmpipe 软件 OpenGL，草无投射阴影、太阳阴影关闭、单 surface/单材质、alpha cutout。读取的是稳定三帧 Godot Performance 计数，不是 GPU API 抓帧或手机测试。风开关和雪天没有改变该样板的 draw call；风运算仍有顶点成本，雪天 discard 仍提交顶点。开启阴影、级联、反射、额外视口或更换渲染器后须重测 pass 与提交量。

不得宣称手机 FPS、GPU 耗时、功耗、温度或正式道路持续驾驶性能已验证。软件 GL 只证明该路径能渲染和计数，不能证明物理 GPU 性能。

正式集成后，固定相机、分辨率和画质比较草开/关、风开/关；记录实际 draw call、三角形、CPU/GPU 帧时间和内存。在目标设备测近地满屏草、急转镜头、跨 LOD/流送边界、晴雪恢复、冷启动与长时间温升。优先检查交叉面片的 overdraw、填充率、带宽和顶点负担，再决定降低密度、视距或面片复杂度；不要仅凭合批数量判断移动端可用。

## 6. 复用来源

相对共同工作根目录查找 `grass_wind027/`，先核对当前文件与证据 hash。它不随本技能打包，也不是已合入主世界的实现。

- `project/shaders/grass.gdshader`：高度平方风动、alpha cutout、距离淡出与雪天。
- `project/scripts/grass_field.gd`：交叉分段网格、轮廓 mask、实例数据和块级 LOD。`INSTANCE_CUSTOM.r/g/b/a` 分别为相位、色差、纵向尺度、冬季稳定随机数；改约定时同步修改 shader。
- `INTEGRATION_NOTES.md`：正式世界接入顺序、遮罩、包围盒和远景注意事项；不要整体复制 `demo.gd`。
- `PERFORMANCE_REPORT.md`、`evidence/draw_call_profile.json`：实测计数及限制。
- `evidence/render.json`、`evidence/tests.json`、`evidence/bounds_analysis.json`：GL 读回、输入不变量和解析包络。实际场景修改后重新验证，不沿用样板 PASS。
