# 离线资产制作

## 树与岩石

旧山路树生成器是 Python 标准库离线写 GLB：米、+Y、地面原点、identity transforms，Branches 与 Foliage 分离，固定种子、有限面数、顶点色、无运行时生长。树干用沿切线的低边数环连接，枝条有受控方向变化，冠形按物种与种子变化。GLB 的 CCW 正面和 Godot 直接 SurfaceTool 的 CW 正面分开验证。

旧树默认近/远上限 1,200/350 三角，樱树单独 2,200/450；两个不透明材质、无纹理。它是当前生成器的预算，不是所有场景必须采用的预算。009–017 新杉林三级树更简洁，不能拿旧 GLB 预算当其实际面数。

制作静态道具时记录近/远 mesh 的真实包络、底部顶点、材料与 hash。若模型有薄片才考虑双面；封闭树石默认背面剔除。不同朝向、尺度、色差不应破坏底部接地或道路净空。

### 可重现检查入口

本包直接提供 `scripts/generate_branching_trees.py`、`validate_tree_glbs.py`、`bake_bare_forest_card.py`。从空输出目录生成，再使用显式 `--output` / `--input` 参数检查，完整命令和依赖见 [portable-tools.md](portable-tools.md)。`--check` 只读已生成结果；打包适配后的生成器hash不同，不能沿用旧项目manifest。

## Geometry Nodes 建筑

项目已实现真正的 Blender Geometry Nodes 网络，而不是仅把脚本建好的完整模型挂上空节点组：输入为空，宽/深/层数/层高/开间/屋顶升高/墙材质等参数参与求值。以形体与接口参数化，不把同一高模缩小冒充 LOD。

推荐流程：
1. 定义 footprint、楼层、屋顶、正门/后勤门与台阶锚点。
2. 生成墙/屋顶/门窗组件，入口所在窗组明确排除，按面方向计算窗框朝向。
3. 分别设计 LOD0/LOD1，远景减少窗框/屋檐/装饰但保留建筑身份。
4. 求值后应用并导出 GLB，保留可重复生成脚本与 .blend；游戏只加载静态结果。
5. 重新导入导出的 GLB 做结构和图像检查，不只看 Blender 源对象。
6. 检查参数扰动后确实改变尺寸，再恢复并验证可复现；界面参数范围不等于全部组合均合格。

项目 v2 示例三个住宅和无品牌便利店：近/远面数 920/260、1784/404、1784/404、1898/372；使用八色色板中的七色、共享外部 Godot 材质。+Y 向上、+Z 指前门、基底 y=0、单位根；这与车辆 -Z 向前不同，不能错转。

建筑场景含 FrontDoor/FrontStep，便利店还有 ServiceDoor/ServiceStep。整体摆放优先平移和绕 Y 旋转，不用任意非等比缩放偷适配地块。包络包括屋檐、台阶与后门，不只统计墙身。

v2 碰撞模板默认禁用且 layer/mask=0，由场景统一启用与验证。Color.a 是雪曝光数据，不是透明度；屋顶/台阶曝光与屋檐遮蔽单独定义。材质有 snow_amount 接口不代表已接入主世界天气。

### 复用生成器时

定位 `fuji_geometry_nodes_assets_v2` 或对应更新资产根目录，再读脚本路径与依赖：

```sh
blender -b -t 2 --python source/build_node_assets.py
bash source/run_checks.sh
blender -b -t 2 --python source/render_assets.py
```

这些命令会生成资源/证据，只在授权的隔离资产副本内运行。不要把整个资产目录直接覆盖已有世界色板、manifest 或共享 shader。

## 资产交付合同

每项至少提供：稳定 ID、来源/许可、工具版本与 seed、生成参数、导出 hash、单位/轴向/原点、真实 bounds、LOD 网格及切换范围、材料/贴图/透明模式、可变状态、碰撞默认态、入口/接地锚点、天气通道和原生验证结果。

LOD 距离取决于实际镜头和设备。v2 建筑 0–110 m/110–420 m 是已有候选配置，不是未经实测即可保证的通用设置。建筑遮雪描述按实例计数，不能把四种模块误算为全村只有四个遮蔽槽。
