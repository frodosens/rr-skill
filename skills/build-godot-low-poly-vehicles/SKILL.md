# 制作 Godot 低多边形汽车

把汽车制作拆成“外形、视觉绑定、物理边界、验收”四件事。先保留项目能开的车，再替换造型，不为看起来像参考车而偷偷改轮距、碰撞或动力。

## 先读什么

- 修改现有项目：读 [项目实现与接口](references/project-implementation.md)，核对当前分支、源码和测试，不能把历史参数当最新事实。
- 新建或改外形：读 [建模与材质方法](references/modeling-method.md)。
- 接入或交付：读 [验证与性能](references/validation.md)。

## 1. 固定范围与输入

1. 先区分玩家车、NPC 车、只供展示的模型；记录 Godot 版本、渲染器、目标设备与当前资源预算。
2. 读项目 AGENTS.md、相关视觉构建器、物理车体和截图脚本，保存当前差异。只改授权文件，保留其他人的工作。
3. 实际查看参考图和当前游戏截图。提取车长/车宽比例、车顶线、轮拱、前后悬、灯组、进气口、尾翼、配色等识别点。
4. 将“已有事实”“本次目标”“尚未验证”分开记录。参考图片只指导原创形状；需要使用外部模型、字体或贴图时核对授权。
5. 项目示例使用米、+Y 向上、局部 -Z 向前。原点、轮心和物理尺寸以当前车体接口为准，不统一强行改原点。

## 2. 先轮廓，后小细节

1. 以当前轮心为基准画正面、侧面和俯视比例，确定允许的视觉包络。
2. 车身用沿 Z 排列的截面放样，保留引擎盖、腰线、尾部等大平面，用少量窄倒角接面。
3. 车舱用倾斜前后窗、收窄车顶、A/B/C 柱建立轮廓。采用不透明蓝灰玻璃，不用透明度遮掩错误的几何接合。
4. 轮拱做真正的开口和回折边；宽体可改外壳宽度，不能顺带移动接地点。检查压缩、转向与滚动时的穿插。
5. 最后添加车型辨识件。宽体拉力车优先保留宽后肩、机盖进气口、金色轮毂、尾翼和排气轮廓，不增加无助于实际镜头的微细节。
6. 先检查中性光照的多角度图，再检查正常游戏追车镜头。不要用特写好看替代游戏内可读性。

## 3. 构建可维护的网格与材质

- Godot 原生 SurfaceTool/ArrayMesh 按材质聚合静态车身；独立保留需要转动的轮组与有独立状态的灯。
- 每个面使用有限、归一化的几何法线；跳过或拒绝退化三角形。Godot 直接网格按顺时针正面约定验证；不要把 glTF 的逆时针约定直接抄过来。
- 小而固定的共享材质集：车漆、深色橡胶、蓝灰玻璃、金属、灯罩、尾灯。大面积车漆保留宽高光，少用高金属度与低粗糙度。
- StandardMaterial3D 的颜色与写入顶点/自定义 shader 的颜色管线分别检查，不能统一套额外 gamma 转换。
- 封闭车身背面剔除，不增加局部灯、反射探针或透明玻璃来补错误形体。
- 普通材质可共享，刹车强度等可变状态必须实例隔离。车辆池只换已有色板绑定，不逐次克隆共享车漆。
- 不在每帧重建网格。玩家切换时构建视觉；NPC 按车型缓存网格，四轮可用同一 MultiMesh。

## 4. 接入原车控制

1. 保持现有 player/body 对象与相机、HUD、交通对它的引用。
2. 视觉构建器返回项目需要的根节点、四轮、前轮枢轴和尾灯引用；先确认数组顺序，别把按左右分组与按前后轴分组混淆。
3. 转向枢轴与滚动子节点分离；由现有物理轮速、实际转向角和刹车状态驱动。
4. 视觉变更默认不改碰撞体、轮接触、悬挂、轮胎、齿比或动力。若本次另有获批动力配置，单独实现并验收，不声称外观参考车的真实 AWD/发动机模型已实现。
5. 重复选择保持幂等；玩家接口拒绝非法 ID 并保留当前状态，NPC 未知 kind 才回退 sedan_a，损坏的玩家存档则按现有加载规则回退红车。暂停切换保留位置/速度/瞬时动力状态，持久化测试用隔离路径，不覆盖玩家存档。
6. NPC 视觉无自主移动和物理回调，由交通控制器调用；净空尺寸包含后视镜和完整转向/滚动包络，不等同精确碰撞体。

## 5. 完成门槛

执行 [验证清单](references/validation.md)，至少核对几何、绑定、状态隔离、渲染和回归。

交付包含：修改范围、模型接口、面数与材质/表面计数、真实引擎截图、实际执行的测试结果、来源与未验证项。只做模型图库截图时明确它不是驾驶画面。桌面软件渲染、低面数和 headless 通过均不能证明手机帧率或触屏手感。

不要因本技能而自动发布、导出 APK 或扩大修改范围；发布按当前用户授权与仓库流程执行。
