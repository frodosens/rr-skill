# 日本靠左道路生成

把道路形状、交通语义、图形表现和车辆行为分开，再用同一份语义数据连接。保持现有已验收世界、原车物理、导航 ID 和非本次修改不变。

## 1. 确认真实输入与能力

1. 找到实际运行的 `project.godot`、入口场景、WorldManager、manifest、道路图、保存路面和本轮允许改动目录。不要按目录名字猜生产入口。
2. 读取 [project-evidence.md](references/project-evidence.md) 选择已有实现；它是 2026-11-06 的快照，不是永久真相。核对当前源码和证据再复用。
3. 冻结输入路径、generation、SHA-256、道路 ID、范围、chunk owner、语义端口和保护区；支持面不匹配就停止该部分生成。保留已有远端和并行修改，不用整目录覆盖。
4. 为结论标明 `implemented / design_assumption / proposed / verified_scope`。代码存在不等于已集成，局部测试不等于全图通过。
5. 只整理规则时交付规则与计划，不顺带修改世界。实施时先选一个授权范围内的小样，验证后再扩展。

## 2. 固定左行坐标

使用 Godot 米制、Y 向上；图上方为 -Z，右方为 +X。令中心线递增方向的水平单位切向为 `F`，`U=(0,1,0)`，几何右向为 `R=F.cross(U)`。

- 不为改成左行而翻转中心线、`R`、UV、路网 ID 或左右转含义。
- 行驶方向 `d` 为 +1 或 -1，驾驶前方为 `F*d`，驾驶右方为 `R*d`。
- 左侧车道中心偏移为 `lateral=-d*lane_center_distance`，位置为 `P+R*lateral`。正向负偏移，反向正偏移。
- 双向对称、每向一车道且无特殊路肩时，可用车行总宽 `W/4` 作为初始车道中心距；随后按实际有效车道、车宽和余量验证。旧项目 `3.0` 或 `2.85` 米不是通用值。
- 4.4 米窄住宅路不要机械画两条标准车道或认定可全速会车；单独检查车体包络、错车与步行冲突。
- 运行 `python3 scripts/check_conventions.py --self-test` 检查本技能数学示例；它不替代项目几何与驾驶测试。

## 3. 生成道路与接入

按 [geometry-and-streaming.md](references/geometry-and-streaming.md) 执行。

1. 从已确定路线、路级、端口和现有地形出发，沿地势使用连续长坡和圆顺弯，不随机铺环路或因标线重画道路。
2. 对中心线采样，声明桩号采用平面 XZ 弧长还是 3D 弧长。生成稳定断面，检查重复点、自交、窄弯内侧折叠和纵横坡。
3. 从同一断面生成沥青、路肩、步道、路缘和入户接驳；在入口边界插入采样点，按同一高程降路缘，不用重叠平面或隐藏碰撞桥补缝。
4. 新道路可见顶面和碰撞取同一最终三角形。修整路下地形与周边过渡，按完整铺装范围排除植被。
5. 任意交叉口、汇入、道路并集、桥梁及地块自动规划不是 006 生成器已有能力；先单独设计拓扑，不把两条 ribbon 相交当完成。

## 4. 先定交通语义，再画线与字

读取 [traffic-and-lettering.md](references/traffic-and-lettering.md)。推荐每条规则保留：

`road_id, station_basis, start_m, end_m, direction, road_width_m, lane_layout, priority, stop_required, speed_limit, allowed_turns, turnaround_allowed, source_rule, review_status`。

护栏开口另记 `barrier_opening`；未知项用 `null/unknown`，不要默认为允许。这是推荐的跨系统语义表，不是声称现有 006/016 已有完整接口。

- 区分中央线、同向车道分界线、车道外侧线、路侧带、停止线、横断步道与装饰性减速标记。
- 没有明确交通控制，不从曲率、路宽或路口数量推断黄色实线、禁止超车、停止、限速或掉头许可。
- 给停止控制绑定来车方向、停止位置、冲突区和 NPC 停车点。`止まれ` 是停止，`徐行` 是能立即停车的慢行，不能互当“让行”。
- 使用正确日文字形：`減速`，不要用简体 `减速`；`止まれ`、`徐行`、`カーブ注意` 按语义使用，不把中文“等待”直接印在日本路面。
- 文字放在该方向左侧行驶车道，文字顶部朝行驶前方；反向旋转整个排版 180°，不得镜像字形。
- 不把沿弯前进箭头画成越过中心线的掉头箭头。`転回禁止` 是禁止掉头；`転回場所` 仅可作为已核实私人场地的说明。
- 016参考参数：白线宽0.15米、边线中心距车行边缘0.30米、中心虚线3米/间隔5米。它们是游戏方案，不是日本所有道路法定标准。
- 虚线相位绑定整条道路桩号原点，跨128米块不重置。在真实路口、接入和平台按语义中断，不能穿过停车场/建筑入口。

## 5. 贴合真正的保存路面

1. 把标线多边形与当前道路 ID 匹配的真实支持三角形逐片裁切。
2. 用同一个支持三角形的平面/重心插值计算 Y；不要只贴理想样条、旧8米高程场或双线性扭曲四边形。
3. 保留 owner、支持资源哈希和三角形索引。跨块输出只归属一个 owner。
4. 将0.008米竖直抬升视为起点，检查法线、Godot正面绕序、float32退化和俯视/贴地/远距闪烁。不要不断抬高变成悬浮贴纸。
5. 使用共享哑光材质、离线字形遮罩和mipmaps，不发光、不投影、不生成碰撞、不改抓地或限速；保留字体许可。

## 6. 护栏与雪天

- 从道路左右真实路缘、落差、外坡、水边、桥头和离路轨迹生成危险区间，不随机撒护栏。对已识别危险区间要求连续覆盖，检查端头和跨块接缝。
- 将入口/步道/排水口作为语义开口，复核安全地形、端头退让与车辆扫掠。悬崖不能因开口而留下直接坠落路径。
- 使用可见栏杆对应的简化连续碰撞，避免空气墙和每根立柱的活跃刚体。装饰木栅不能自动视为车辆防坠设施。
- 读取实际天气注册和材质替换路径。给标线明确 `snow_surface_kind=road_paint`，防止节点名误分类。
- 保持雪覆盖、风吹雪、车辙和路面纹理坐标契约一致，不为字清楚而取消全路覆雪。
- 注意：016统一世界实测走非区域 `road_paint.gdshader` 雪材质路径；旧路面UV2车辙与统一世界沥青的世界坐标雪扰动不保证逐像素相同。独立fixture成功不证明主世界使用该路径。
- 测试晴→雪→晴原材质恢复、重复注册去重、雪天加载、卸载清理与缓存不增长。雪天物理变化必须属于本次明确范围，不随视觉更新添加。
